RESUMEN DEL PROYECTO

CONCEPTO

Juego de rol 2D narrativo para Android, orientado al aprendizaje de idiomas.

El jugador aprende el idioma de dos formas:

Mediante el contenido creado por el guionista.
Mediante la interacción y las decisiones durante el juego.

La idea principal es que el aprendizaje esté integrado en una aventura y no parezca simplemente un curso o un test.

El proyecto se desarrollará inicialmente sin minijuegos. Primero se quiere conseguir una versión funcional basada en mapas, PNJ, conversaciones, experiencia, niveles e inventario. Los minijuegos podrán añadirse posteriormente si aportan valor real al aprendizaje.

MECÁNICA PRINCIPAL

El mapa contiene:

Player.
PNJ.
Elementos interactivos.

Cuando el player se acerca a un PNJ, se inicia automáticamente su conversación.

El nivel lingüístico del player determina qué guion se carga.

Hay cinco niveles:

A1
A2
B1
B2
C1

El jugador acumula experiencia mediante las conversaciones.

Cuando consigue suficiente XP, sube de nivel.

Los niveles y sus límites de XP todavía no están definidos definitivamente.

SISTEMA DE GUIONES

Los guiones están almacenados en archivos TXT.

Nombre del archivo:

mapa_nombre_nivel.txt

Ejemplo:

pueblo_anciano_a1.txt

Las tres partes son únicas y no pueden contener "_":

mapa = nombre del mapa
nombre = nombre del PNJ
nivel = nivel lingüístico

No se permiten espacios y se utilizan minúsculas y caracteres alfanuméricos.

Si no existe un guion para el PNJ y nivel correspondiente, se utilizará un guion por defecto.

ESTRUCTURA BÁSICA DEL GUIÓN

[START]

Texto de conversación.

Texto de respuesta -> etiqueta
Texto de respuesta -> etiqueta | efectos

[etiqueta]

Texto.

[END]

OPCIONES

Formato:

Texto de la respuesta -> destino

Ejemplo:

¿Dónde está el castillo? -> castillo

Una opción puede tener efectos:

Tengo la llave -> entrada | -llave_castillo, xp+50

EFECTOS

XP:

xp+20

xp-30

Se decidió utilizar esta sintaxis porque es sencilla para el guionista y fácil de interpretar por el parser.

OBJETOS

Añadir objeto:

+llave_castillo

Eliminar objeto:

-llave_castillo

Los objetos actualmente son únicos.

Si el jugador ya tiene un objeto y el guion intenta añadirlo otra vez, no se duplica y no ocurre nada.

Si se intenta eliminar un objeto que no existe, no ocurre nada.

CONDICIONES

Las condiciones sirven para realizar bifurcaciones automáticas según el inventario.

Formato:

?objeto | SI->etiqueta | NO->etiqueta

Ejemplo:

?llave_castillo | SI->con_llave | NO->sin_llave

No es obligatorio que existan las dos ramas.

Ejemplo válido:

?llave_castillo | SI->con_llave

En este caso solo se ejecuta la rama SI.

También es posible:

?llave_castillo | NO->sin_llave

No es necesario que existan SI y NO simultáneamente.

Una condición sin ninguna rama no es válida.

FINAL DE CONVERSACIÓN

[END]

Los nodos sin opciones también pueden terminar la conversación mediante una espera del programa de prueba.

La conversación termina cuando se alcanza END.

PARSER

Se ha creado un parser funcional en Python.

Archivos actuales:

dialogue_parser.py
dialogue_game.py

El guion se pasa como parámetro:

python dialogue_parser.py pueblo_anciano_a1.txt

Para ejecutar una conversación:

python dialogue_game.py pueblo_anciano_a1.txt

ESTADO DEL PLAYER

El estado del jugador se guarda en:

player_state.json

Actualmente contiene:

{
"xp": 70,
"inventory": [
"espada",
"llave_castillo"
]
}

El estado se carga al iniciar dialogue_game.py.

GUARDADO EN TIEMPO REAL

Se decidió que el estado se guarda inmediatamente cuando cambia.

Cambios que provocan guardado:

xp+20
xp-30
+objeto
-objeto

Si una operación no cambia realmente el estado, no se guarda.

Ejemplo:

+espada

Si el jugador no tiene la espada:

Se añade.
Se guarda inmediatamente.

Si ya tiene la espada:

No se añade otra.
No es necesario guardar.

MECÁNICA EDUCATIVA

Una idea central del juego es que el guionista formule preguntas donde solamente una respuesta sea coherente.

Las demás respuestas son "trampas" diseñadas para obligar al jugador a comprender la pregunta.

Ejemplo conceptual:

¿Qué necesitas para abrir la puerta?

Una llave.
Un bocadillo.
Un caballo.
Ayer por la tarde.

La respuesta correcta proporciona progreso/XP.

Las respuestas incorrectas pueden conducir a otras ramas de la aventura.

La intención es evitar que el juego sea simplemente un test. Las decisiones lingüísticas deberían tener consecuencias narrativas y formar parte de la aventura.

RIESGO PRINCIPAL

El mayor riesgo del proyecto no parece ser la programación.

El mayor riesgo es el contenido.

La cantidad de guiones será lo que haga grande el juego.

Será necesario crear muchas conversaciones de calidad para cada:

mapa + PNJ + nivel.

También será importante evitar que el juego se convierta simplemente en:

pregunta → cuatro respuestas → XP.

El objetivo es mantener el equilibrio entre:

AVENTURA
+
COMPRENSIÓN DEL IDIOMA
+
PROGRESIÓN
+
NARRATIVA

OTRAS DECISIONES DE DISEÑO

No se quiere añadir todavía un sistema complejo de scripting.

El formato debe seguir siendo fácil de escribir para alguien que no sea programador.

El parser debe encargarse de validar errores.

En el futuro será interesante detectar:

nodos inexistentes
etiquetas inexistentes
nodos inaccesibles
condiciones incorrectas
opciones incorrectas
guiones sin START
guiones sin END
objetos mal escritos
posibles problemas de estructura

Después comenzar el prototipo en Godot.
