
Un RPG 2D narrativo para aprender idiomas mediante la creación y la experiencia de juego. 
El aprendizaje ocurre en dos direcciones: 
1. el guionista aprende mientras crea las conversaciones y 
2. el jugador aprende mientras explora el mundo, conversa con sus personajes y toma decisiones.



Actúa como diseñador y analista de videojuegos especializado en RPG 2D narrativos para dispositivos Android y en desarrollo con Godot.

Quiero definir el concepto y las características de un videojuego con las siguientes especificaciones.

==================================================
CONCEPTO DEL JUEGO

Es un juego de rol 2D narrativo para Android.

El jugador explora diferentes mapas, habla con PNJ e interactúa con elementos del escenario.

La narrativa y la progresión del jugador se basan principalmente en las conversaciones.

Los PNJ tienen diferentes guiones de conversación y estos pueden cambiar según el nivel del jugador.

El jugador puede obtener experiencia tomando decisiones durante las conversaciones.

La experiencia permite progresar a través de cinco niveles:

A1
A2
B1
B2
C1

Cada nivel tiene su propia experiencia.

El nivel actual del jugador determina qué guion de conversación utilizar con cada PNJ.

==================================================
EXPLORACIÓN

El juego está compuesto por diferentes mapas 2D.

Cada mapa puede contener:

PNJ.
Objetos.
Elementos interactivos.
Zonas de interacción.
Caminos y obstáculos.
Elementos relacionados con la narrativa.

El jugador puede desplazarse por el mapa y explorar libremente las zonas disponibles.

Cuando el jugador se acerca a un PNJ, la conversación se inicia automáticamente.

==================================================
PNJ

Cada PNJ tiene un nombre único dentro del contexto necesario para identificar su guion.

Cuando el jugador se acerca a un PNJ, el juego determina:

El mapa actual.
El nombre del PNJ.
El nivel actual del jugador.

Con esos datos busca el guion correspondiente:

mapa_nombre_nivel.txt

Por ejemplo:

pueblo_anciano_a1.txt
pueblo_anciano_b1.txt
castillo_guardia_c1.txt

Si no existe un guion específico para el nivel del jugador, se utiliza:

default.txt

==================================================
CONVERSACIONES

Las conversaciones están almacenadas en archivos de texto (.txt).

Esto permite crear y modificar conversaciones sin modificar el código del juego.

Cada conversación está formada por nodos.

El nodo inicial es:

[START]

Los nodos pueden contener:

Texto del PNJ.
Opciones del jugador.
Efectos.
Bifurcaciones automáticas.

Una opción tiene este formato:

Texto de la opción -> nodo_destino

Ejemplo:

¿Dónde está el castillo? -> castillo
==================================================
EXPERIENCIA

Las conversaciones son la principal fuente de experiencia.

Una decisión puede modificar la experiencia del jugador.

Para añadir experiencia:

xp+20

Para quitar experiencia:

xp-20

Ejemplo:

Ayudar al anciano -> recompensa | xp+50

La experiencia no puede ser inferior a cero.

La experiencia acumulada determina la progresión del jugador entre los niveles:

A1 -> A2 -> B1 -> B2 -> C1

==================================================
INVENTARIO

El jugador dispone de un inventario de objetos.

Los objetos son únicos y no se pueden duplicar.

Para añadir un objeto:

+objeto

Si el jugador ya posee ese objeto, no ocurre nada.

Para eliminar un objeto:

-objeto

Si el jugador no posee ese objeto, no ocurre nada.

Ejemplos:

+llave_castillo
-llave_castillo

==================================================
BIFURCACIONES

Las conversaciones pueden cambiar según los objetos que tenga el jugador.

Formato:

?objeto | SI->nodo

?objeto | NO->nodo

?objeto | SI->nodo_si | NO->nodo_no

Las ramas SI y NO son opcionales.

Debe existir al menos una.

Las condiciones son automáticas: el jugador no las ve.

Ejemplo:

?llave_castillo | SI->tiene_llave | NO->no_tiene_llave

Si el jugador tiene la llave, se dirige automáticamente a:

[tiene_llave]

Si no la tiene:

[no_tiene_llave]

Las condiciones actualmente solo comprueban la existencia de objetos.

==================================================
EFECTOS DE LAS OPCIONES

Una opción puede producir uno o varios efectos.

Los efectos se separan mediante comas.

Ejemplo:

Entregar la carta -> despedida | -carta_castillo, xp+50

Esto elimina la carta y añade 50 XP.

También:

Recibir recompensa -> recompensa | +espada, xp+100
==================================================
PROGRESIÓN NARRATIVA

La progresión del juego debe estar basada principalmente en:

Exploración.
Conversaciones.
Decisiones.
Obtención de objetos.
Uso de objetos.
Experiencia.
Cambio de nivel.

Los diálogos pueden ofrecer diferentes caminos dependiendo de las decisiones del jugador y de los objetos que posea.

Los diferentes niveles del jugador permiten crear conversaciones adaptadas a su progreso.

==================================================
DISEÑO DE LA NARRATIVA

La narrativa debe favorecer:

Exploración.
Curiosidad.
Descubrimiento.
Decisiones del jugador.
Recompensas narrativas.
Consecuencias de las decisiones.
Rejugabilidad.

Los PNJ deben tener personalidad y objetivos propios.

Las conversaciones no deben limitarse a proporcionar información: deben servir también para descubrir lugares, conseguir objetos, desbloquear situaciones y avanzar en la historia.

==================================================
ARQUITECTURA GENERAL

El juego debe separar claramente:

PLAYER

Movimiento.
Nivel.
Experiencia.
Inventario.
Interacción.

NPC

Identidad.
Zona de interacción.
Inicio de conversación.

DIALOGUE MANAGER

Selección del archivo de diálogo.
Carga del diálogo.
Gestión de nodos.
Gestión de opciones.
Bifurcaciones.
Ejecución de efectos.
Finalización de conversaciones.

DIALOGUE PARSER

Lectura de archivos TXT.
Conversión del texto a una estructura de datos.
Validación de nodos.
Validación de destinos.
Validación de efectos y condiciones.

DIALOGUE UI

Texto del PNJ.
Opciones del jugador.
Indicadores de interacción.
Transiciones entre nodos.
==================================================
PLATAFORMA

El juego está destinado principalmente a Android.

La interfaz debe estar diseñada pensando en:

Pantallas táctiles.
Diferentes resoluciones.
Botones suficientemente grandes.
Lectura cómoda del texto.
Controles sencillos.
Bajo consumo de recursos.

El juego debe desarrollarse utilizando Godot.

==================================================
OBJETIVO DEL DISEÑO

Crear un RPG 2D narrativo en el que la conversación sea una mecánica central.

El jugador debe sentir que hablar con los personajes, tomar decisiones y explorar el mundo son partes fundamentales de la progresión.

El sistema debe ser sencillo de ampliar: añadir un nuevo mapa, PNJ o conversación debería requerir principalmente crear nuevos archivos de diálogo y configurar los elementos correspondientes del mapa, sin necesidad de modificar el código principal.

==================================================
INSTRUCCIONES PARA EL DISEÑO

Cuando propongas sistemas o soluciones para este juego:

Prioriza la simplicidad.
Prioriza la facilidad de creación de contenido.
Evita sistemas innecesariamente complejos.
Mantén los guiones accesibles para personas que no saben programar.
Diseña pensando primero en Android.
Diseña los sistemas para Godot.
No añadas funcionalidades que no sean necesarias sin explicarlas previamente.
Mantén separados los datos narrativos y la lógica del juego.
Prioriza sistemas modulares y fáciles de ampliar.

Este documento define el concepto base del juego. Las características futuras deben ser compatibles con esta filosofía.
